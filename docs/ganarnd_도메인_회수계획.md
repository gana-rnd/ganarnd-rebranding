## 3. 2026-08-28 추가 조사 — "후이즈에 묶여 있다"의 실체와 Vercel 이전 검토

### 3.1 묶여 있는 것은 두 겹이고, 서로 다른 회사다

| 겹 | 회사 | 근거 (2026-08-28 재조회) |
|---|---|---|
| 도메인 등록(등록대행자) | **㈜후이즈** | KISA whois: `등록대행자 (주)후이즈`, 만료 2030-10-05, 등록인 박용호 개인, 책임자 메일 `dydgh416@naver.com` |
| DNS·웹·메일 호스팅 | **사이트쿡(sitecook.kr)** — 후이즈와 무관한 별개 업체 (등록인 장문섭·금천구, 등록대행자 아사달) | NS 4개 전부 `ns*.sitecook.kr` / 웹서버 183.111.100.218 (KT) / 빌더 `에이빌더`(`/cooker/`, `BUILDER_core8`, 테마 business08) / MX → `webmail.ganarnd.co.kr`(112.175.246.28) |

즉 "후이즈에 묶임"은 정확히는 **등록만 후이즈, 실제 운영은 사이트쿡**. 도메인 통제권(네임서버 지정·기관이전)은 후이즈 쪽에 있고, 사이트쿡은 그 아래서 DNS·웹·메일을 돌리는 임차 구조.

### 3.2 새로 확인된 지렛대 — 후이즈 로그인 없이도 도메인을 빼올 수 있다

- **KISA 인증코드 조회 서비스** (whois.kr → 부가서비스 → 도메인 인증코드 조회): 등록대행자와 무관하게, **도메인에 등록된 휴대폰번호 또는 이메일로 본인인증**하면 기관이전용 인증코드(최대 32자)를 바로 받는다.
- 기관이전 승인 메일(신규 등록대행자 → 기존 후이즈 순으로 2회)도 **등록인 이메일 `dydgh416@naver.com`** 으로 간다. 무응답 시 5~6일 후 자동 승인.
- 따라서 **아버님의 네이버 메일(또는 등록 휴대폰) 협조 한 번**이면 후이즈 계정 복구 없이 새 등록대행자 계정으로 이전 가능. 후이즈 계정 복구는 "네임서버만 바꾸고 후이즈에 남는다"를 택할 때만 필요.

### 3.9 결정: 등록인 개인 명의 유지 (2026-08-28)

### 3.10 관리 계정 ≠ 등록인 구조와 메일 재확인 (2026-08-28)

**구조**: 등록대행자 "회원 계정"과 도메인 "등록인(소유자)"은 별개 층이다. 회사 계정이 도메인을 관리하고 등록인은 박용호로 남는 구성은 정상이며 흔하다. 가비아 기준 권한 분리:

| 소유자 인증 없이 회사 계정이 하는 것 | 등록인 인증(이메일·휴대폰)이 필요한 것 |
|---|---|
| 연장 결제·자동연장 · 네임서버 변경(안전 잠금 OFF일 때) · 부가서비스 · 대장 관리 | 소유자명·소유자 이메일·소유자 휴대폰·관리자 이메일 변경 · 소유권 이전 · 타 기관 이전 · 안전 잠금 해제 |

**핵심**: 등록인 *이름*과 등록인 *인증 채널*은 별개 필드다. 이름은 아버님 그대로 두고, **소유자 인증용 이메일·휴대폰을 회사(담당자) 채널로 갱신**하면(현 채널로 1회 동의) 이후 모든 인증을 회사가 통과한다. 이때 안전 잠금을 켜도 해제 키가 회사에 있다. 아버님 채널을 그대로 두면 잠금 해제·정보 변경마다 아버님 인증 → 그 경우 안전 잠금은 켜지 말고 이전 잠금만.
→ 07단계에 반영: "관리자 이메일 → 회사"에 **소유자 인증 이메일·휴대폰 → 회사 담당자**를 추가. 아버님께 한 문장: "이름은 그대로, 알림과 인증만 회사 번호·메일로 돌립니다."

**`@ganarnd.co.kr` 메일**: 사이트쿡 웹메일이 살아 있다(`webmail.ganarnd.co.kr` 로그인 페이지, SMTP/POP3/HTTPS 열림). 사용자 수·계정 목록은 사이트쿡 관리자 모드에서만 확인 가능.
→ 계획 변경: 메일은 "확인 후 폐기"가 아니라 **사용 중 전제로 이관 설계** — 08단계 MX·SPF·webmail A 복제 필수, 11단계 사이트쿡 해지 전 메일함 백업·신규 공급자(Google Workspace / 네이버웍스) 이관·MX 교체 필수.
